# 自动关闭 Codex 后合并本地对话

## Goal

让用户可以先打开 Codex 客户端，运行配置脚本完成路径和进程探测，并在选择 `Y` 合并本地对话时，由脚本关闭已检测到的 Codex 桌面实例、确认会话数据库不再被占用，然后继续本地迁移。

## Background

- 当前脚本会独立解析 `CODEX_HOME`：`--codex-home`、环境变量 `CODEX_HOME`、最后是 `~/.codex`。桌面进程只能补充安装路径和运行状态证据，不能直接作为配置目录。
- 当前脚本检测到 `codex ... app-server` 后，如果用户选择 `Y`，会在任何目标文件写入前报错退出。
- Windows 实机证据显示桌面窗口根进程是 `ChatGPT.exe`，`codex.exe app-server` 是其子进程；只结束后端或按进程名批量结束都不安全。

## Requirements

1. 保持现有 `CODEX_HOME` 解析优先级。打开 Codex 是可选的路径/进程证据来源，不把应用安装目录误当成配置目录。
2. 用户选择 `N` 时，不关闭任何进程，不读取或改写会话数据库，不改写 rollout 会话文件。
3. 用户选择 `Y` 且未检测到桌面后端时，继续现有迁移流程。
4. 用户选择 `Y` 且检测到桌面后端时，该选择同时授权脚本尝试关闭这一已验证的 Codex 桌面实例，不再要求用户重新运行整套配置。
5. 脚本必须先请求桌面应用优雅退出并等待最多 15 秒；关闭期间输出中文状态，且不得输出 API Key。
6. 优雅退出 15 秒后目标仍在运行时，脚本必须重新验证 PID、可执行文件、`app-server` 命令行和进程树身份；验证一致后自动强制终止这一实例并等待完全退出。
7. 关闭目标必须从已检测到的 `app-server` PID 和进程父子关系推导，只能操作同一应用安装根目录内的 GUI 根进程或后端，禁止按 `ChatGPT`、`Codex` 等名称批量结束进程。
8. 如果配置脚本本身位于目标 `app-server` 的子进程树中，必须在关闭前停止并提示用户改用系统 PowerShell/Terminal，避免脚本自我终止后留下半完成状态。
9. 只有在重新探测确认目标 Codex 后端已退出，并通过 SQLite WAL/SHM 与锁状态检查后，才能创建备份和写入配置、模型目录或会话元数据。
10. 关闭失败、权限不足、强制终止后仍未退出、目标身份变化或退出后仍有匹配后端时，必须在任何目标写入前报错；不得继续迁移。
11. `--detect-only` 和 `--dry-run` 不关闭进程。`--dry-run` 只报告正式执行时将关闭的 PID、强制回退策略和计划迁移内容。
12. 脚本不自动重启 Codex。配置完成后提示用户重新启动客户端。
13. 该流程仍只修改本地 provider 可见性元数据，不上传历史消息、项目、附件或源码。
14. GitHub Release 必须提供可直接粘贴执行的一行式 Windows PowerShell 命令；在 Python 3.11+ 已安装的电脑上，该命令完成下载、SHA-256 校验并启动交互配置，无需克隆仓库或手工填写仓库名、标签和缓存路径。
15. macOS/Linux 文档提供等价的一行式命令。单行入口仍必须先把固定 GitHub Release 资产保存到临时目录并校验，禁止使用 `curl | sh`、`irm | iex` 或其他未经校验的远程代码直执行方式。

## Acceptance Criteria

- [x] Windows、macOS/Linux 的进程控制逻辑均可通过注入的进程记录、信号发送器和等待器测试，无需在测试中结束真实 Codex。
- [x] Windows 可从 `codex.exe app-server` 推导同一安装目录内的 GUI 根 PID；不会把 `explorer.exe`、终端、普通 Codex CLI 或其他 ChatGPT 进程纳入关闭目标。
- [x] 活跃桌面实例下选择 `Y` 会调用关闭流程，退出确认后在同一次运行中完成备份和迁移。
- [x] 活跃桌面实例下选择 `N`、`--detect-only` 或 `--dry-run` 均不会调用关闭流程。
- [x] 脚本从目标 Codex 进程树内运行时，选择 `Y` 会在写入前给出外部终端提示。
- [x] 优雅关闭失败或权限错误时，配置、模型目录、rollout 和 SQLite 保持原字节不变。
- [x] 优雅关闭超时后会重新验证目标并强制终止；PID 被复用或身份不一致时拒绝强制操作。
- [x] 关闭后后端重新出现时，迁移被拒绝。
- [x] 中文输出说明正在关闭、关闭结果、失败原因和重新启动要求。
- [x] Windows 用户只需粘贴一行命令即可下载并验证最新版 bootstrap，然后进入 Key 输入、模型选择和对话合并流程。
- [x] 单行命令不执行未校验的远程脚本文本，下载或 SHA-256 校验失败时不启动配置程序。
- [x] 全量单元测试、Python 编译、PowerShell 解析和 POSIX `sh -n` 通过。

## Out of Scope

- 从应用安装路径反推或覆盖 `CODEX_HOME`。
- 关闭普通 Codex CLI、IDE 扩展或与已检测桌面实例无父子关系的进程。
- 自动重新启动 Codex。
- 上传、复制或重放任何历史对话内容。
- 通过降低下载校验标准来缩短命令。
